Set up Driftless in this repository.

Driftless keeps Markdown docs tied to source symbols. It saves reviewed source hashes in `.driftless.lock` and fails later when code changes so related docs are reviewed too.

Goal: keep docs and source behavior in sync without making user-facing docs worse.

Steps:
1. Check whether `driftless` is installed. If it is missing, install the latest GitHub Release:
   `curl -fsSL https://raw.githubusercontent.com/akshay5995/driftless/main/install.sh | sh`
   Then run `export PATH="$HOME/.local/bin:$PATH"` for the current shell and verify the installation with `driftless --version`.
2. Inspect the source layout, public docs, and maintainer docs.
3. Identify behavior worth locking: public APIs, commands, config keys, examples, package exports, and workflows.
4. Add refs where they help the reader. Prefer maintainer docs for implementation contracts.
5. Avoid noisy refs in user-facing docs unless the link naturally helps.
6. If no maintainer doc exists, create a short one that explains source ownership.
7. Run `driftless check --json` before updating the lock. Use each record's doc section and `symbol_source` to repair stale or misplaced prose.
8. Run `driftless update` only after docs and source have been reviewed.
9. Run `driftless check`.
10. Commit `.driftless.lock` with the docs.

Ref forms:
- Inline code: `path/to/file.rs#symbol_name`
- Markdown link: [symbol](path/to/file.rs#symbol_name)
- Fenced code info string: use an opening fence like `rust ref=path/to/file.rs#symbol_name`

Important: do not run `driftless update` merely to silence failures. Fix docs or source first, then refresh the lockfile.
